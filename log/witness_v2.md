# Check-witness obligation, v2 shipped contracts (2026-11-10)

Follow-up to the contract-mutation result of `log/campaign_v2.md` section 3: the directed scenarios
fired only 10 of the 65 distinct checks of the five scored contracts, so most check mutations could
only be noticed by A2U. Obligation (user decision 2026-11-10, "write proof for each"): every
distinct check of every shipped ROM package has a witness, i.e. a concrete run in which that
check is part of the monitor's first verdict while the package's environment assumptions hold up
to that point. A check without a witness is dead (it can never be the first verdict) and is a
contract defect.

Per-check results: `log/witness_v2_table.md` and `log/witness_v2.csv`, both generated by
`formal/mutation/v2/witness_report.py`.

## 2. Method

### 2.1 Formal cover (94 checks)

One harness per check, `w2_<pkg>_<F|B><code>` (`formal/src/witness_v2.ml`, `Ag_pkg` `Cover`
mode). The bad signal is "the monitor's first verdict contains this check, and the package's
environment assumptions have held so far".
- Blame checks: shipped firmware on the spec lane, free peer (`uio_in`), free host streams.
- Fail checks: free chip outputs (`Ag_pkg ~free_chip`), free peer. The shipped firmware cannot
  be the witness here: its U proof states no fail without an earlier blame.

Engine: ABC `dprove`, 1,800 s per check, 9 parallel jobs, 63 min wall
(`formal/mutation/v2/run_witness.sh 9 1800`). Each counterexample is replayed in cyclesim
(`replay_cex`), and the interpreter is run on the trace's monitor inputs.
- Witness depth: 1 to 4,476 frames (median 11).
- Longest: w2_i2c_ctl_fm_B76 (1,492 s), w2_i2c_ctl_fm_F72 (998 s, 4,476 frames).

9 checks timed out (OPEN): i2c_ctl_fm B77, i2c_ctl_sm B77, i2c_tgt F54 F55 F56 F57 B58 B81, usb FA4.

### 2.2 Directed witness search (9 checks)

The obligation is existential, so one concrete run suffices. `mutants_v2.exe wsearch <pkg> <F|B><code>`
(`formal/bin/mutants_v2.ml`) searches as follows:
- Blame checks: the shipped firmware against peer parameter families.
- Fail checks: single-instruction firmware mutants (nop, wait ±1, out/oen bit flips, ldi/cmp/addi ±1,
  branch condition flip or target ±1, jmp/djnz ±1) on a fixed nominal scenario.

A hit is a Psim run whose first verdict is the target check. Every hit is re-run on the v2 chip RTL
(cyclesim of `Top_v1` with the shipped library v2inc5, `lane_pipe`, `verdict_pipe` and
`param_windows`, i.e. the tape-out candidate configuration). It is accepted only if the chip's
first verdict of that role is the target code, no earlier than any verdict of the other role.

| check | statement | witness | first verdict, Psim = chip RTL (cycle) |

| usb FA4 | frame.await (SE0 within data_max + 1 steps) | 9 x 0xFF payload; firmware 6 `Mov R2 R1` (length copy) -> `Nop` | fail A4 @ 2481 |

Notes:
- The i2c_tgt families gained two additions: an SDA-pull overlay (500 start positions at 50-cycle
  pitch, lengths 261 and 30), and a 16-byte write base for F56. With the nominal 2-byte write, the
  STOP resets the frame guard long before the 4095-step push window can expire. USB gained 9/10/12/15-byte 0xFF
  payload bases (bit stuffing pushes the packet body past data_max = 102 bits).
- Each new fail base gives no verdict with the shipped firmware, on Psim and on the chip
  (`mutants_v2.exe wbase`): i2c_tgt long16 16 pushes, chip RX 16 bytes; usb long9ff..long15ff no
  verdict, one status push each (the shipped firmware does not send the over-length packet; the
  mechanism, presumably the length check, was not traced). So each fail witness is due to the mutant,
  not to the scenario.

### 2.3 Harness corrections found on the way

1. `chip_run` (rtl_v1/test/test_c3_diff.ml) wrote all TX bytes before the run, so bytes beyond the
   8-deep TXF were dropped. Psim's host instead refills TXF whenever FIFO_ST shows room. The first
   USB FA4 hit was therefore "not confirmed": the chip underran and took the legal abort path. New
   opt-in `?stream`: preload at most 8 bytes, then poll FIFO_ST and write one byte per SPI
   transaction. New `?rx_drain` (stream mode only): pop RXF one byte at a time when FIFO_ST shows
   RX data. Both default to off, so existing tests are unchanged.
2. F56 was first "witnessed" on long16 with a non-draining host (`rx_pop_every` 10^9): fail 56 @ 47935,
   after 8 pushes, with the shipped firmware on both Psim and chip. That run violates the documented
   host-stream assumption "the RX FIFO is never full" (`doc/protocols/i2c_v1.md`, target section),
   so it is not a valid witness. It was replaced by the draining-host witness above. See section 3.

## 3. Finding: an unmonitored host assumption surfaces as a fail

Observed (Psim and chip RTL agree): if the host stops draining RX during a long write to the I2C
target, the run shows 8 push events (the RXF depth) and then none; the contract's frame watcher
reports fail 56 (push missing) at cycle 47935. Whether the lane blocks or drops at a full RXF was
not examined for this note. The protocol document lists "RX FIFO never full" as a
host-stream assumption checked outside the monitor, so this is the documented behaviour. In a
demo, however, it reads as a chip guarantee violation caused by the host, which is exactly the
blame/fail confusion the assume-guarantee design is meant to prevent. The same pattern applies
to any package with an unmonitored host-stream assumption (i2c_ctl also assumes RX never full).

Decision for the user:
1. Document only (`docs/info.md` host requirements, demo host drains RX). No RTL change. The fail
   still mis-attributes if a user's host violates the assumption.
2. Make RX-full observable to the monitor (e.g. an `rxf_full` observable usable in contracts) and
   blame it in the i2c contracts. This is an RTL change on the tape-out candidate: re-synthesis,
   CI and the equivalence/sign-off chain must be re-run.
3. Host-side guard only: the RP2350 host package (plan step 10) asserts the drain rate and flags
   the run as host-invalid. No RTL change, but only covers the reference host.

## 4. Limits

- One witness per check code. Several codes are shared by many statements (e.g. spi_tgt B52 by 16
  statements, i2c_tgt F55 by 8). This campaign does not show that every statement can fire. A
  per-statement obligation is a possible extension (sites per code: `mutants_v2.exe wlist`).
- Directed witnesses are simulation runs, not formal counterexamples. Existence is shown
  concretely on Psim and on the chip RTL (the interpreter is the Psim monitor). For these 9 checks
  the formal harness timed out at 1,800 s, and nothing was concluded formally.
- Peer overlays act on cycle counts of the controller model. A witness position (e.g. pull from
  10100) is specific to that peer timing.
- Gate level: not re-run for these witnesses. The demo board has shown RTL == GL on 17 scenarios
  (`log/demo_v2.md`); the witnesses were not added to the GL set.

## 5. Use for the contract-mutation score (not done)

The 103 witnesses are a check-level regression: replaying each witness against a mutated
contract would kill every code bump and role swap on a witnessed check, plus any weakening that
removes the witnessed firing. The undetected contract mutants of `log/campaign_v2.md` section 3
(63/100, of which 0/14 code bumps and 0/3 role swaps were caught) could be re-scored with this
oracle. Cost estimate: directed witnesses in Psim take seconds. Formal witnesses need the
interpreter replay of 94 counterexample traces per mutant (replay_cex already decodes monitor
inputs), estimated well under an hour for 100 mutants.
